# 上櫃歷史資料日常閉環：來源→60 日門檻→指標／SMC→評分→核對

問題：原本 `tpex-official-insert-only-history.yml` 每週二至週六
02:10 的正式排程只執行官方資料**只新增**，新跨過 60 日門檻的
股票必須等到獨立的指標補算或一次性授權標記才可能完成最新評分。
舊一次性 10 檔驗收成功，不代表日常工作也會自動閉環。

**這次已修正**而且沒有新增定時 GitHub Action 或 API 額度：

- 官方 TPEx 每日仍 **最多 10 檔 × 五個官方月份（50 次）**，只新增
  缺漏 `daily_prices` 主鍵，不覆寫已存在行情。
- 成功通過官方價格來源驗證後，**同一個排程**會啟動
  `new_eligible_score_followon.py` 兩輪，各最多五檔：
  補建調整價格、技術與 SMC，並只新增當日缺漏的綜合評分；
  不會為既有約千檔完整評分重算全市場。
- 該日工作最後一定執行 `eligible_100_catchup.snapshot`
  核對 **同股同最後有效收盤日的技術、SMC、非 NULL 綜合評分**；
  任一股票未達成則本次 GitHub 工作標示失敗，而非顯示
  「成功卻有研究池缺口」。
- **所有**上櫃來源工作（包含正式排程、手動、一次性標記）
  和每日指標回補改用已有
  `twstock-indicator-catchup` concurrency 群組，防止同一時刻
  一邊新增原始行情、一邊依舊數字進行最新評分／核對。
- 仍使用原有 GitHub Free、Neon Free、800MB 儲存停止線。
  單一來源 API 失敗則不自行加速重試；全部紀錄留在原本
  14 日 GitHub artifact。
- 無 LINE 訊息、無交易、無任何額外定時任務。
- 合格股票池的 100% 不代表全部 1,991 檔歷史資料 100%，
  更不代表 Ridge AI 模型有正的真實樣本外 alpha。

本改動**只修復後續正式排程的閉環**，對還沒有發生的未來
交易日與官方史料不預先填入。官方資料不足股票維持
`LESS_THAN_60_VALID_SESSIONS`，不得「補滿 60 日」的假數據。
