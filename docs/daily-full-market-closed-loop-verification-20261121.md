# 台股下一階段：免費排程內自動驗證最新指標、SMC 與綜合評分

2026-11-21，現有 1,109 檔有效研究池已驗證 **同股、同最新有效收盤交易日**的技術、SMC 及綜合評分達 100%。但這不是全部 1,991 檔歷史行情、研究因子或 AI 策略獲利能力的 100%。

這次只修改原本就有的 `TW Stock Data Quality Monitor (Read-Only)`；**不新增另一個每天跑的 GitHub Action**、不增加任何付費 API 或服務，沒有自動推薦、LINE 訊息及券商交易操作。現有 Neon 專案為免費方案，當前資料庫約 228 MB，仍低於既有 800 MB 保守停止線。

## 現在可持續運作的流程

1. `daily-bounded-history-enrichment.yml`：既有小批量官方歷史回補。
2. `tpex-official-insert-only-history.yml`：每週二至週六台北時間 02:10，最多 10 檔 × 5 個官方月份，不呼叫付費資料服務；原價表只做 `ON CONFLICT DO NOTHING`，不覆寫已存在交易日。
3. `daily-indicator-catchup.yml`：03:10，最多每市場 20 檔有至少 60 日真實行情的股票，計算調整資料、技術與 SMC。
4. `composite-after-market-refresh.yml`：只有已授權成功的正式交易日來源或指標排程，才觸發原有綜合評分更新；手動需明確 `apply=true`。
5. **原有** `twstock-data-quality-monitor.yml`：04:00，以 Neon 單一 `REPEATABLE READ READ ONLY` 快照與 30 秒 SQL timeout，計算每檔**最後有效收盤日**的三項交集。輸出中只有按市場彙總統計，不曝光資料庫密碼或個股評分。

> GitHub Actions 排程開始時間不保證精確。各來源／計算工作可能延遲或失敗，報告必須以最後資料庫實際狀態為準。排程設定不等於曾經成功執行。

## 每日報告改進

`src/stock_db_audit.py` 增加 `COHORT_INTERSECTION_SQL` 與 `validate_cohort_intersection`。新回傳：

- `cohort_by_market`：各市場 stock_master 分母、沒有收盤、低於 60 日、研究例外、行情過期、合格股、當日技術、當日 SMC、當日評分以及**確實同時擁有三者**的交集數。
- `matched_cohort_coverage`：兩個分母與真實百分率、待補當日指標／評分檔數、四類缺口的總數。
- 同股同日交集數不可能大於單項指標或評分；五種互斥人數分類必須恰好等於 stock_master，否則中止，不顯示錯誤的 100%。
- 新的報告放在**已有的**每天品質監控 `GITHUB_STEP_SUMMARY` 與原有的 7 日彙總 artifact，不新增永久資料表，也不要求新的帳戶權限。
- 研究分類只要求每股有 60 個有效行情日；**不代表** MA120、MA240 均有足夠歷史，更不代表基本面、籌碼、歷史樣本外、流動性和實際交易成本已驗證。
- 模型先前使用過的 holdout 淨超額研究結果約 -2.11 個百分點；根據 2026-07 至 10 月資料，完整且不重疊的歷史報酬觀察窗仍不足最低研究門檻。本次**不重訓／重啟／推送模型**。
