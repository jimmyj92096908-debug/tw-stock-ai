# LINE 股票代碼與完整中文名稱查詢：程式驗收

## 支援指令（正式候選上線後）

- `6213`、`分析 6213`、`股票 6213`：四位數代碼直接查詢
- `聯茂`、`分析 聯茂`、`股票台積電`、`環球晶`：依 `public.stock_master` **完整相同名稱**查詢，不猜測部分名稱、不以拼字接近度代替
- `清單`、`1` 到 `10`、`資料狀態`、`研究報告`、`模型狀態`、`說明`：保留原有候選指令
- 如果名稱在市場間重複，回覆候選代碼與市場，要求使用者用四位數代碼確認；被排除的 `1808` 不進入分析
- 股票名稱以外的普通文字（例如 `你好`）及群組／非文字事件仍轉送原本 `linewebhook`

## 自動研究回覆內容

每次回覆標示股票名稱、代碼、上市／上櫃、收盤交易日、漲跌、量、9 條均線、RSI、ATR、SMC 趨勢與結構事件、Order Block／FVG、綜合分數、短中長期分數、籌碼覆蓋程度、短中期趨勢解讀、歷史 20 日低高價與波動提醒；過期或不同步資料均加註風險。約束在 LINE 單則訊息 4,900 字以內。

**重要：** 這是以 Neon 已存的官方歷史行情生成的**研究分析**，不是即時報價、證券投資顧問推薦、獲利保證或個別交易訊號。當財報、籌碼或分析因子資料未齊備，回覆會明確標示，不會杜撰基本面、法人交易或預測價格。現有 `tw-factor-ridge-1` 模型樣本外績效未通過，所以 LINE 不會提供可交易的買賣訊號。

## 路由／隱私／安全

- bare 漢字名稱：只有通過驗簽、完整私聊 reply contract 且 `STOCK_NAME_SQL` 返回精確匹配，才路由至股票查詢；其餘仍走原有舊版入口，不截取普通聊天
- 明確指定 `分析 聯茂` 等名稱：直接進入候選股票查詢，查無完全匹配就回覆清楚原因
- 股票名稱以參數化 SQL `$1` 查詢，嚴禁 ILIKE、SQL 字串拼接、部分名稱推斷
- 正式候選 DB reader 只允許 `ANALYSIS_SQL`、`RANKING_SQL`、`DATA_STATUS_SQL`、`STOCK_NAME_SQL` 四段固定 SELECT，舊版 webhook forwarding 維持原主機與簽章驗證
- 原有事件紀錄與回覆狀態去重、三次重試和 1 分鐘 replyToken 限制維持不變；不從檔案或日誌保存 LINE channel 密鑰
- 測試覆蓋真假簽章、普通文字保留、重名、排除股票、正式 Neon 6213 唯讀 SQL、PostgreSQL 17 一次性隔離 DB 及現有 LINE 抽象端對端整合

## 從 GitHub 到正式 LINE 的未完成門檻

GitHub CI 測試通過／候選程式打包 `≠` Neon 新部署成功 `≠` 官方 LINE Webhook 正式切換。現有 Neon `linestockgateway` 仍缺兩項同頻道受保護憑證名稱 `LINE_CHANNEL_SECRET`、`LINE_CHANNEL_ACCESS_TOKEN`，現有程式不能代替真實密鑰。不得複製、印出或寫入版本控制。

須由有權限的維運者以 LINE Developers 的正式頻道資料在 Neon 受保護設定配置，於新閘道維持 disabled 模式時部署並驗證官方簽章空事件，再用真實受控 LINE 測試帳號驗收名稱／代碼／一般訊息／去重／轉送與回復計畫，最後才切換註冊 Webhook。整個過程不影響當前舊 LINE 服務與每日報告。
