## 發現並修正的程式問題（僅草稿分支）

1. **LINE 每日資料報告：** 原先使用最新行情日當作評分日，當計分批次尚未完成時，會顯示空清單。改為分別取得最新已完成評分日和最新行情日，並只以評分當日有非空收盤價者製作觀察名單；回覆中明確寫出兩個日期及日期不符提示。修改 `src/send_line_report.py`，新增 `tests/test_send_line_report_queries.py` 等測試。
2. **LINE 排行：** `RANKING_SQL` 加上評分當日非空收盤價的條件，避免沒有可配對價格的標的以完整排名形式呈現；仍保留原有 `1808` 排除規則。修改 `line-stock-analysis/handler.mjs`。
3. **輪替下載公平性：** 原本所有無行情股票排前面，擁有歷史行情但資料過期的股票可能長期被擠出批次。改為「尚無有效收盤價」與「已有有效收盤價」**交錯輪替**，並使用上次嘗試時間讓各群輪轉；不提高既有每市場預設批次上限、也不主動觸發下載。修改 `src/full_market_refresh.py`。
4. **資料品質診斷 CLI：** 新增 `src/stock_db_audit.py`，只使用 SQL SELECT，並在讀取時強制設定唯讀交易。輸出覆蓋率、最新行情／技術／SMC／評分日期、最新評分同日價配對數與部分個股資料日期；沒有憑證輸出或私人 LINE 使用者資料。
5. **LINE「資料狀態」與「說明」：** 在**未切換的**新功能路由加入明確指令，查詢已存資料的最新日期與涵蓋率；不聲稱即時更新。非股票及非明確指令仍轉送原本 `linewebhook`。

## 綜合評分重算排程缺口與預設關閉的修補

檢查 GitHub 主分支 `.github/workflows/build-composite-scores.yml` 發現：原本只在 `workflow_dispatch` 或評分程式/設定檔有變動時執行，**沒有**在每日行情更新成功後自動重算，因此價格資料可能比評分新。這是需要獨立處理的排程問題，不能以改報告顯示日期代替重算。

已在草稿分支新增：
- `scripts/score_after_refresh.py`：沿用現有 `calculate_all`，但只列出處理檔數，不將資料庫連線字串或大量逐股票資料寫入 CI 日誌。
- `.github/workflows/composite-after-market-refresh.yml`：可在 `Full Market Daily Data Rotation` 成功完成後連動評分，但**必須先由具權限的管理者明確設置** `ENABLE_AUTOMATIC_COMPOSITE_SCORES=true`，否則自動資料庫寫入工作保持停用。手動觸發也預設 `apply=false`，不會寫入。
- `tests/test_score_after_refresh.py`：驗證輸入、日誌沒有憑證、以及自動重算必須有明確 opt-in 條件。

**本次沒有設定 ENABLE_AUTOMATIC_COMPOSITE_SCORES，也沒有觸發評分寫入、部署或正式 Webhook 切換。** 這個方案在 PR 未合併前不影響既有排程，之後若要啟用還需另行確認預期的資料庫寫入量、批次先後順序和交易日曆。
