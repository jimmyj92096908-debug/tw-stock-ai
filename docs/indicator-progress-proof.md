# Indicator batch: before/after evidence validation

This read-only proof validator can be used after a separately authorized
indicator-writing job. It **does not** connect to Neon, change production
workflows, or enable a write schedule.

Input files are generated by the already deployed read-only
`scripts/indicator_schedule_probe.py` before and after the batch. Run:

```bash
python scripts/indicator_batch_reconcile.py \
  --before indicator-before.json \
  --after indicator-after.json \
  --output indicator-progress-proof.json
```

For each `twse` and `tpex` market, it requires a self-consistent
`eligible = pending + complete` count, a stable global latest price date,
and unchanged eligible market size. A market with pending candidates must
show strictly fewer pending stocks **and** the same increment of complete
stocks. A market with zero pending before and after is a valid no-work
result. Invalid, missing, or changed evidence is a failed proof.

The output includes explicit `progress_verified`, per-market deltas
and the limits of the aggregate evidence. A failed proof exits nonzero
and can prevent downstream score refresh when added to an **approved**
write workflow.

This does not prove causal impact by itself: if another writer updates
indicators concurrently, aggregate totals may change. Run-level indicator
logs and individual upsert verification remain necessary. Neither a
successful proof nor a test result authorizes a trading signal, LINE
cutover or automatic production writes.
