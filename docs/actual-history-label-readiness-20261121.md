**研究用途；沒有實際交易、LINE 推播或新增付費服務。**

目前 Neon 正式資料庫已核對到同股票／同最新有效交易日：
`1,109 / 1,109` 檔符合 60 日歷史及日期條件的股票，均已有
技術指標、SMC 和有效綜合評分；不能和整個 `stock_master = 1,991`
檔的 100% 混淆。仍有 871 檔有價但不足 60 日、9 檔完全沒有
有效收盤價；另有不在現行研究集合的股票。官方史料逐步回補
仍需尊重交易所資料來源、免費額度和真實上市／停牌狀態。

## 主要驗收問題

**最新資料完整** ≠ **歷史期間可以證明 AI 預測有效**。

舊模型 `tw-factor-ridge-1` 的歷史樣本外資料曾被檢視，
平均淨超額報酬約 **-2.11 個百分點**，舊 holdout 不獨立、
研究閘門不通過。即使當天可用股票達 1,109 檔，也不能拿它
替換舊 holdout 或假設已有 1,109 檔 × 60 日的歷史評分。

`scripts/historical_label_readiness.py` 針對已有保存評分的
**整個訊號日股票池**，唯讀檢查：

1. `t` 當日的已有評分及調整收盤價都有效；
2. 只在 `t+1` 個真實交易日以調整收盤作為示意進場基準，
   `t+6` 個真實交易日作為示意出場，兩者必須早於已知
   `label_cutoff`，未到期不能計為有效報酬；
3. 不能只刪除缺少未來報酬的個股，須**排除整個日期的股票池**；
4. 同一天所有個股必須有**相同實際入／出場日期**，
   否則即使資料不缺，也不得直接比較其 Top 20%；
5. 任何研究前，先刪除**與已選持有期重疊**的訊號日期，
   並要求至少 10 個不重疊完整窗、且跨越 60 日曆日。
   這只代表**有最低探索資料量**，絕不代表
   模型通過統計顯著性、流動性和樣本外驗證。

## 2026-11-21 實際唯讀 SQL 實測

資料庫實際保存的 2026 年歷史評分、調整價與未來交易日標籤，
以 `2026-11-20` 為最後已知交易日。此為**現存歷史資料的當前快照**，
不是當時已封存的原始逐日資料版本，不能證明歷史資料
在訊號當下就存在，故不屬於全新獨立樣本外驗證。

| 項目 | 2026-09-01 至 10-31 | 2026-07-06 至 10-30 |
|---|---:|---:|
| 有至少 10 檔評分的訊號日 | 39 | 79 |
| 缺任一未來標籤的日期 | 12 | 26 |
| 持有日期不一致的日期 | 22 | 44 |
| 全股票池完整且日期一致 | 5 | 9 |
| 排除重疊後獨立研究窗 | **2** | **4** |
| 通過至少 10 個不重疊窗門檻 | **否** | **否** |

這些是**實際官方行情衍生的資料庫聚合品質檢查**，
不是績效計算或新的正超額證據。研究不足不是「資料已補到
100% 仍無法計算分數」，而是「目前儲存的歷史模型評分，
尚無足夠多同期間、未來標籤完整的可比獨立觀察」。

## 如何執行（不新增排程）

離線驗收已備妥的每日彙總 JSON：

```bash
python scripts/historical_label_readiness.py \
  --source-json historical-daily-label-aggregates.json \
  --start 2026-07-06 --end 2026-10-30 \
  --cutoff 2026-11-20 \
  --output-json research-label-readiness.json \
  --output-md research-label-readiness.md
```

若已確認本輪免費額度，可**由人工明確執行一次只讀**
Neon 聚合查詢（不傳出任何個股的原始評分），仍強制
最多 120 個日曆日窗口、`REPEATABLE READ READ ONLY`
交易、20 秒逾時與 120 筆訊號日上限：

```bash
HISTORICAL_RESEARCH_LABEL_READONLY=yes DATABASE_URL='<existing-protected-url>' \
python scripts/historical_label_readiness.py \
  --read-neon \
  --start 2026-07-06 --end 2026-10-30 \
  --cutoff 2026-11-20 \
  --output-json research-label-readiness.json \
  --output-md research-label-readiness.md
```

不應自動大量重跑 Neon 掃描。沒有足夠樣本時，
`eligible_for_exploratory_outcome_research=false`，
`model_alpha_approved=false`、`orders_enabled=false`。
未到期的未來結果須等真實交易日到來，不能透過重複補算
或放寬資料閘門來「製造」足夠樣本。
