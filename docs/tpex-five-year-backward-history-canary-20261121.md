# TPEx 五年官方行情：先做兩檔非覆寫、可回滾的回溯試點

2026-11-21 的正式資料庫唯讀核對：上櫃 879 檔至少有 60 日真實價格、歷史因子已有 879/879 完整吻合；但 861 檔僅 60–119 個有效行情日、2 檔 240–999 日、16 檔 >=1000 日。因此「歷史因子 100%」**不是**「五年 OHLCV 100%」。

## 試點設計與限制

- 新增 `scripts/tpex_long_history_ladder.py`，**只選取**最新一週有價、60–999 個有效日、最早已觀察日期不超過五年的上櫃股票，不臆造掛牌日；排除代號 1808。
- 以最早實際有價月份為**來源錨點**，最多查同月及往前四個月。每次最多 **2 檔 × 5 個官方月請求＝10 次**，不跳過已知來源的月份。另至少要求該錨點月有 2 個已保存、與官方相同的收盤價；不吻合則整檔拒絕。
- 官方 `TPEX_TRADING_STOCK` 驗證沿用已經有測試的交易日、OHLC、代號、成交量等規則，無成交／停牌的日期不偽造；只向 `daily_prices` 執行 `ON CONFLICT ... DO NOTHING`，保留所有既有價格。只在成功實際新增、沒有增加或失敗後更新既有來源嘗試狀態，兩天冷卻以免無成長重試占滿工作。
- 每檔交易前後校驗有效日數、最早日、最新日及**800MB Neon Free 安全線**。一檔失敗就回滾該檔插入；其他股票不受影響。不更新任何因子、評分、交易或 LINE。資料新匯入後需依既有因子管線另行重算，並驗證新日期因子，不得沿用先前 879/879 當作新版價量因子已完整。
- 新增的 GitHub Actions **只有手動 workflow_dispatch**，預設 apply=false 是純預覽；沒有新定期任務，也不在 merge 時自動觸發正式寫入。正要寫入必須手動選 apply=true；只使用專案已有的 DATABASE_URL 私密環境變數。
- 月端點若無較早資料、來源被限流、或股票是真實新上市，報告 `failed`／`no_growth`，不能增加分子或假造「五年完整」。觀察到 >=1000 日仍不等同所有官方五年交易日逐日覆核。

## 安全試點的成功定義

先從最多兩檔取得官方前四個月的真實新增日期，並核對歷史最低日確實往前、原有收盤及交易量未被覆寫、增量股數及儲存容量；確認源可靠後再獨立規劃可負擔的免費多批輪替。五年所有檔全面回補的時間仍取決於來源可取得性、交易所限流及 GitHub/Neon Free 額度。
